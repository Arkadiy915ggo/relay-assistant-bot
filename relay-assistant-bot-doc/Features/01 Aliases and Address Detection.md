# Feature 01: Aliases and Address Detection

## Статус

Реализовано. Принятая текущая политика отличается от первоначального admin-only замысла: aliases может добавлять, удалять и перечислять любой участник разрешённого чата. Возможный admin-only toggle отложен и не реализован.

## Цель

Дать каждому чату настраиваемые имена бота. Когда участник пишет одно из них в обычном сообщении или подписи к медиа, бот надёжно определяет обращение, убирает имя из текста и передаёт оставшийся запрос следующей логике. В этой фиче следующая логика остаётся текущим контекстным ответом; LLM-роутер добавляется отдельно в Feature 02.

## Зависимости

Нет. Это фундамент для Feature 02.

## Пользовательский UX

- Любой участник разрешённого чата: `/alias add Реле, Релейка, Рел`.
- Любой участник: `/alias list` видит настроенные формы.
- Любой участник: `/alias remove Рел` удаляет одну форму.
- В личном чате отправитель управляет алиасами тем же способом.
- `Реле, о чём договорились вчера?` вызывает текущий контекстный ответ и отвечает reply на это сообщение.
- `Релейка сделай мем` пока передаётся как обычный вопрос; Feature 02 позже распознает действие `meme`.
- Сообщение только с алиасом получает короткое `Да? Напишите, что нужно сделать.`

## Границы

Входит: хранение алиасов, проверка `ALLOWED_CHAT_IDS`, нормализация, поиск обращения в тексте/caption, удаление обращения, интеграция с пассивными message/media handler-ами, документация и тесты.

Не входит: намерения LLM, вызов других команд, очки, казино, новая модель или новые env-переменные.

## Хранилище

Добавить таблицу `chat_bot_aliases`:

| Поле | Назначение |
| --- | --- |
| `chat_id` | Область видимости алиаса. |
| `alias` | Отображаемая форма, заданная участником чата. |
| `normalized_alias` | Нормализованная форма для поиска. |
| `created_by_user_id` | Аудит изменения. |
| `created_at` | UTC-время создания. |

Ограничение `UNIQUE(chat_id, normalized_alias)` обязательно. Методы `MessageStore` должны быть узкими: добавить, удалить, перечислить и получить нормализованные формы одного чата.

## Правила сопоставления

1. Точный Telegram `@username` сохраняет существующее поведение и остаётся самым надёжным способом обращения.
2. Для алиасов нормализовать Unicode, регистр, `ё -> е` и разделяющую пунктуацию.
3. Сравнивать отдельные токены, а не подстроки: алиас `бот` не должен срабатывать внутри другого слова.
4. Если суммарная длина токенов алиаса меньше 5 символов, сопоставлять только точно. Для формы от 5 символов допустима одна замена, вставка или удаление на весь алиас. В многословном алиасе это одна опечатка всего в одном токене, а не по одной опечатке на каждое слово.
5. Склонения, сокращения и прозвища должны добавляться через `/alias add`; не пытаться угадывать неограниченную русскую морфологию.
6. Если в сообщении несколько алиасов, удалить все совпавшие формы и обработать запрос ровно один раз.
7. Не отвечать на сообщения самого бота и не обрабатывать slash-команды этим путём.

## Техническая интеграция

- `src/tg_summary_bot/storage.py`: таблица, dataclass при необходимости, async CRUD-методы.
- `src/tg_summary_bot/bot.py`: вынести из `bot_mention_question()` общий helper уровня `extract_addressed_request(...)`, который возвращает `None`, пустую строку или очищенный запрос.
- `create_dispatcher()`: добавить `/alias` до пассивных handler-ов.
- Не делать admin lookup: принятая политика разрешает управление aliases любому участнику чата, прошедшего `ALLOWED_CHAT_IDS`. Будущий admin-only режим потребует отдельной настройки и тестов.
- Текущий `save_regular_message()` должен после сохранения вызывать общий обработчик обращения.
- Фото/видео уже перехватываются более ранними handler-ами, поэтому тот же общий обработчик должен вызываться после их пассивного сохранения. Иначе caption `Реле, сделай мем` никогда не дойдёт до адресной логики.
- Канальные `channel_post` не участвуют: там нет диалоговой модели reply и настройки прав отличаются.

## Пошаговый план

1. Добавить таблицу и методы storage вместе с изолированными тестами CRUD и уникальности.
2. Реализовать чистые helpers нормализации, токенизации, ограниченного edit distance и удаления токенов алиаса.
3. Покрыть helpers таблицей случаев: регистр, `ё`, пунктуация, слова-подстроки, короткий алиас, длинная опечатка, несколько алиасов.
4. Добавить `/alias add|remove|list` с понятными русскими ошибками использования и общей проверкой allowlist.
5. Объединить путь `@username` и алиасов в один helper, не ухудшая entity-проверку Telegram username.
6. Встроить helper во все нужные пассивные handler-ы, не допуская двойного ответа одному update.
7. Когда текст после удаления имени пуст, отправлять короткое приглашение; иначе использовать текущий `answer_chat_question(..., reply_to_source=True)`.
8. Обновить `/help` и README с примерами управления алиасами.
9. Запустить unit-тесты и `python -m compileall src`.

## Критерии готовности

- Алиасы одного чата не видны и не работают в другом.
- Любой участник разрешённого чата может менять список; admin-only ограничение отсутствует намеренно.
- `@username` продолжает работать без настроенного алиаса.
- Алиас распознаётся в caption изображения и видео.
- Одна входящая реплика даёт максимум один ответ.
- Ложное совпадение внутри другого слова не вызывает бота.
- Многословный alias принимает не более одной опечатки суммарно.
