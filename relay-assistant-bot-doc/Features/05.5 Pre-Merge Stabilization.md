## Зафиксированные исправления

### Актуальный доступ к durable work

- Planning, job claim/reclaim и outbox claim/reclaim применяют текущий `ALLOWED_CHAT_IDS` и joke-disabled policy.
- При пустом allowlist доступны все чаты, как в остальных операциях бота.
- Убраный из allowlist чат не получает новые награды, уведомления или автоматические casino actions из уже накопленной очереди.
- Исключённые jobs/outbox остаются без потери состояния; возвращение доступа разрешает продолжение.
- Startup casino recovery возвращает pending stakes в SQLite независимо от allowlist; Telegram leaderboard refresh применяется только к разрешённым чатам.

### Устойчивость autonomous worker

- Создание/чтение activation point находится внутри retry loop.
- При временной ошибке SQLite повторяется инициализация; backfill запускается только после успешного activation point.
- Backfill повторяется до успеха, а не отмечается выполненной после ошибки.
- Poll interval ограничивает частоту повторов.
- Unexpected task failure логируется через completion callback; штатная cancellation не считается crash.

### Casino settlement

- Один reserve → один Telegram Dice → до 3 попыток сохранения одного и того же trusted результата.
- Backoff: 0.25 и 0.5 секунды. Повторное отправление Dice запрещено.
- Ошибка после фактически committed payout обрабатывается idempotent replay, без второй выплаты.
- После исчерпания попыток ручной вызов получает предупреждение без деталей базы и без заявления о начисленных очках.
- Pending stake остаётся для startup refund; это не обещание немедленного возврата при недоступной SQLite.
- Cancellation во время settlement пытается выполнить shielded idempotent refund и пробрасывает cancellation.

### YouTube abandonment cleanup

- Timeout/cancellation выставляют stop signal, но не отменяют task так, чтобы потерять финальные записи download thread.
- Thread cleanup и completion callback удаляют abandoned prefix после последних записей, включая поздний successful download.
- Соседние download prefixes и успешно полученный вызывающим кодом результат не удаляются.
- Upstream sign-in/anti-bot failure остаётся известным ограничением; cookies не добавлены в этом этапе.

### YouTube successful-download handling

- `max_downloads=1` удалён из library options: настоящий `yt-dlp` выбрасывал `MaxDownloadsReached` после успешного первого скачивания. Раньше бот воспринимал это как failure и удалял готовый файл.
- Single-video admission по-прежнему обеспечивается URL/metadata validation и `noplaylist`; playlists/live/unknown-duration checks сохранены.
- Регрессия проверена на настоящем управляющем коде `yt-dlp`, с подменой только extraction/download I/O. Сеть и FFmpeg для этого теста не нужны.
- Это отдельная исправленная программная ошибка. Реальное скачивание с YouTube после исправления не проверялось; cookies, требования авторизации и ограничения сети остаются отдельной диагностикой. Блокировка IP не установлена.

### Текущая policy для уже сохранённой outbox

- `AUTONOMOUS_JOKES_SHADOW_MODE=true` приостанавливает всю outbox предыдущего live run, без claims и увеличения attempts. Startup void/refund для незавершённых ставок остаётся самостоятельным recovery contract.
- `BOT_AUTO_CASINO_ENABLED=false` приостанавливает queued automatic spins; `AUTONOMOUS_JOKE_ANNOUNCE=false` приостанавливает queued notifications.
- При возвращении toggle в enabled работа может продолжиться, в том числе для старых записей. Сохранённый casino decision не пересэмпливается.
- SQL action filtering исключает paused actions до claim: они не блокируют разрешённый leaderboard refresh.

### Турнир длинных кандидатов

- Когда каждый finalist образует отдельный singleton batch, следующий round сравнивает пары вместо повторной оценки каждого отдельно.
- Serialized JSON ограничен character budget с учётом envelope/escaping. Длинный текст представлен началом и концом с маркером ` […] `; пропущенная середина может содержать шутку, которую модель не увидит.
- Canonical source IDs и исходные тексты не сокращаются. Award/quote используют оригинал; invalid model IDs и `no_joke` продолжают валидироваться по прежнему контракту.
- Manual и worker callback paths используют общий tournament algorithm. Если не помещается даже metadata, selector возвращает `prompt_budget_too_small` без model call.

### Конкурентный leaderboard refresh и command admission

- Refresh одного чата сериализован от чтения balances до edit/create/save/pin через process-local async lock. Запоздалый snapshot не перезаписывает более свежий результат другого refresh; два первых refresh не создают два leaderboard messages.
- Другие чаты независимы. SQLite write lock и `gpu_lock` не удерживаются во время Telegram I/O; cancellation освобождает refresh lock.
- `/casino` проверяет `ALLOWED_CHAT_IDS` до usage reply, чтения aliases и разрешения bot identity, включая неверные аргументы и `/casino bot`.

### Configuration и документы

- `.env.example`, `.env.ollama.example`, Feature 05 и handoffs используют defaults 50 сообщений / partial minimum 5 / 3 дня.
- Исторические jobs с другими policy versions сохраняются.
- README различает текущие runtime-возможности, CLI TTS-эксперименты и будущие дизайны.
