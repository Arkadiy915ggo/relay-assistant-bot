# Feature 06: Voice Message Generation

## Статус

Базовый дизайн, 2026-10-03. В боте TTS пока не реализован. Есть отдельные CLI-эксперименты в `experiments/qwen3-tts/` и `experiments/cosyvoice3/`; их WAV-выходы не являются Telegram voice messages.

Ближайшая новая фича после [[05.5 Pre-Merge Stabilization]]. Связанные продуктовые решения: [[12 Product UX and Portfolio]].

## Пользовательская ценность

Бот может озвучить текст или ответить голосом. Пользователю не нужно запускать локальный TTS CLI, искать WAV и отправлять его вручную. У чата появляется узнаваемый голос бота.

Гипотеза: короткие голосовые ответы полезны в неформальных чатах и для прослушивания на ходу. Проверять на реальных задачах; не включать озвучку каждого ответа без отдельного решения.

Согласно [[01 Product Vision]], голос — часть узнаваемой persona комьюнити. После одного MVP preset предусмотрен выбор между несколькими настроенными голосами и явный запрос «скажи другим голосом»; voice choice и формальность профиля должны быть независимыми. Произвольное клонирование участников не следует автоматически включать в этот следующий этап.

## Предлагаемый MVP

- Одна явно вызываемая операция озвучки текста: предварительный UX `/voice <текст>` или reply `/voice` на текст.
- Один выбранный preset голоса и один TTS provider для первого rollout.
- Результат отправляется как Telegram voice, не как технический WAV-документ.
- Сообщение о подготовке, понятная ошибка и лимит текста/длительности.
- Для contextual voice answer сначала получить обычный текст через assistant, затем озвучить; этот сценарий можно выделить во второй этап.

Массовое клонирование произвольных участников, voice library editor, потоковая речь и автоматический voice mode пока не входят в MVP.

## Execution design

```text
explicit request → validated text / assistant answer
                 → SpeechSynthesizer.synthesize(text, voice_id)
                 → WAV → ffmpeg OGG/Opus → Telegram send_voice
                 → stored spoken text + source metadata → cleanup
```

- `SpeechSynthesizer` возвращает audio path, duration и provider/model metadata.
- Qwen/CosyVoice запускать через отдельный процесс и окружение: у CosyVoice сейчас Python 3.10 и независимые ML dependencies, у бота Python 3.11+.
- Local GPU work использует существующий shared `gpu_lock`, удерживаемый до фактического завершения процесса. Timeout/cancellation сначала останавливают и дожидаются процесса, затем освобождают GPU и удаляют файлы.
- Hosted TTS adapter впоследствии может использовать тот же контракт без локального GPU.
- Для одной операции сохранять один canonical spoken-text source. Не начислять joke points дважды за текстовую и голосовую копии одного ответа.
- Provenance для spoken text и eligibility определить явно: это не incoming Whisper transcript.
- Не переносить тяжёлые зависимости TTS в обязательную установку бота.

## Выбор модели и голоса

Сравнить Qwen3-TTS Base и CosyVoice 3 на одинаковом русском тексте и референсах: разборчивость, сходство/приятность голоса, интонация, cold/warm latency, peak VRAM, reproducibility.

Существующие README содержат локальные наблюдения, а не универсальную гарантию качества. Итоговый preset, provider и правила использования voice references выбрать перед реализацией. WAV post-processing speed/pitch остаётся настройкой preset, а не обязательным пользовательским интерфейсом.

## Критерии приёмки

- Успешный запрос отдаёт playable Telegram voice и сохраняет произнесённый текст для контекста.
- Валидация выполняется до запуска модели; длинный/пустой запрос получает понятный отказ.
- Одновременно не выполняются TTS и другие локальные GPU-задачи бота.
- Сбой отправки/кодирования/синтеза не оставляет временные файлы и не выдаёт ложного успеха.
- Проверить timeout, cancellation, startup без TTS dependencies и API-only installation.

## Метрики и открытые вопросы

Измерять success rate, time-to-voice, длительность речи, peak VRAM и пользовательскую оценку голоса. Численные цели установить после baseline.

- Озвучивать только supplied text или сразу добавить voice answers?
- Какой голос становится default и кто может менять preset в чате?
- Нужна ли текстовая копия по умолчанию или достаточно сохранённого контекста?
- Каковы MVP text/duration limits и нужен ли отдельный queue/status UX?

Команда `/voice`, provider interface и presets — предложения; runtime settings для них пока не добавлены.
