# Feature 04: Casino Slots

## Цель

Добавить виртуальное казино за очки из Feature 03. Пользователь вызывает `/casino`; при наличии Feature 02 та же операция доступна через адресованную фразу `Реле, прокрути казино`. Бот отвечает на это сообщение нативной Telegram-анимацией `🎰`, списывает ставку, рассчитывает выплату и показывает итоговый баланс.

## Зависимости

Для ядра нужна завершённая [[03 Joke Points and Leaderboard]]: неизменяемый ledger, balances и транзакционные методы изменения очков. Интеграция адресованной фразы дополнительно требует [[02 Intent Router and User Actions]]; без неё реализуется только `/casino`.

## Границы

Входит: один слот, фиксированная ставка, анимация Telegram, безопасное списание, расчёт, возврат при ошибке, восстановление незавершённых спинов, сообщения результата.

Не входит: реальные деньги, платежи, переводы очков, ставки произвольного размера, ежедневные бонусы, несколько игр, внешние RNG и изменение правил наград за шутки.

## Правила игры v1

- Ставка: `10` очков. Нельзя крутить при балансе меньше `10`.
- Используется Telegram Dice с `emoji="🎰"`, поэтому клиент Telegram сам показывает анимацию трёх символов слота.
- Результат `Dice.value` сохраняется вместе со спином и является единственным источником выплаты.
- Таблица выплат от ставки 10:

| Комбинация | Возврат | Изменение баланса |
| --- | ---: | ---: |
| Нет совпадений | 0 | -10 |
| Одна пара | 10 | 0 |
| Три одинаковых | 100 | +90 |
| Редкий джекпот | 250 | +240 |

- Точная таблица `Dice.value -> category` должна быть реализована как отдельная проверяемая функция. Перед релизом её надо сверить с реально возвращаемыми значениями Telegram/aiogram и закрепить unit-тестами. Нельзя придумывать комбинацию из value на глаз.
- `/casino` - основной интерфейс. При наличии Feature 02 эта фича добавляет intent `casino` в его schema/allowlist и вызывает ту же операцию только для явной формулировки прокрутки, а не для случайного упоминания слова «казино».

## Хранилище

Добавить `chat_casino_spins`:

| Поле | Назначение |
| --- | --- |
| `spin_id` | Первичный ключ. |
| `chat_id`, `request_message_id` | Идемпотентность запроса. |
| `participant_key`, `participant_name` | Игрок. |
| `stake` | Списанная ставка. |
| `dice_message_id`, `dice_value` | Результат Telegram. |
| `payout` | Итоговая выплата. |
| `status` | `pending`, `completed`, `refunded`. |
| `created_at`, `completed_at` | Аудит и recovery. |

Нужно ограничение `UNIQUE(chat_id, request_message_id)`: повторная доставка одной Telegram-команды не запускает второй спин.

Ledger получает две или три записи: `casino_bet=-10`, `casino_payout=+N`, при сбое `casino_refund=+10`. Каждая операция привязана к `spin_id` и выполняется транзакционно с изменением balance.

## Безопасный жизненный цикл

1. Атомарно проверить баланс, создать `pending` spin и списать 10.
2. Отправить reply-dice `🎰` на исходное сообщение. Telegram возвращает `Message` с `dice.value`.
3. Атомарно записать dice id/value, вычислить payout, создать ledger payout и пометить spin `completed`.
4. Отправить краткий reply с комбинацией/категорией, выплатой и балансом.
5. Если шаг 2 не отправился, атомарно вернуть ставку и выставить `refunded`.
6. При старте приложения находить старые pending spins и безопасно возвращать ставку. Не пытаться угадывать невидимый Telegram-результат после рестарта.

Отправка Telegram и SQLite не могут быть одной распределённой транзакцией. Именно `pending` + идемпотентность + refund закрывают окно между ними.

## Техническая интеграция

- `src/tg_summary_bot/storage.py`: schema, atomic debit/create, settle, refund, stale pending recovery.
- `src/tg_summary_bot/bot.py`: `/casino`, общая `spin_casino(...)`, вызов recovery в startup после `store.init()`.
- Использовать aiogram API для ответа на конкретное сообщение, а не отдельное сообщение в чат без reply.
- Не нужен `gpu_lock`: слот не использует LLM, Whisper или vision.
- `/top` и `/balance` остаются в Feature 03; казино пользуется их storage API, но не дублирует рейтинг.

## Критерии готовности

- Один request message создаёт максимум один спин и одно списание.
- Два конкурентных спина не могут увести баланс ниже нуля.
- При неудачной отправке dice ставка возвращается ровно один раз.
- После restart старый pending spin возвращает ставку и не создаёт дублирующих операций.
- Выплата рассчитывается только из сохранённого `Dice.value`.
- Slot-анимация и итог отвечают на сообщение игрока.
- В коде и документации нет намёка на реальные деньги или вывод очков.
