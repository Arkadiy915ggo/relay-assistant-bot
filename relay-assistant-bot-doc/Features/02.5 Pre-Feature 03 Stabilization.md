# Stage 02.5: Pre-Feature 03 Stabilization

## Статус

Реализовано перед Feature 03. Этот этап фиксирует фактический контракт Feature 01/02 и не реализует очки, выбор лучшей шутки, ledger, balance или leaderboard.

## Цель

Стабилизировать пользовательские операции и наблюдаемость до добавления финансовоподобного виртуального ledger. После этого этапа вызывающая сторона получает терминальный исход операции, сгенерированный контекст сохраняется по best-effort политике, спорные intent-ы не превращаются в неожиданные действия, а принятые исключения явно задокументированы.

## Реализованный контракт операций

Для операций введён `OperationOutcome`:

| Поле | Контракт |
| --- | --- |
| `operation` | Стабильное имя операции: `summary`, `question`, `wiki`, `image`, `video`, `profile_show` и т.д. |
| `status` | Один из `succeeded`, `rejected`, `partial`, `failed`. |
| `reason` | Машиночитаемая причина, например `ok`, `invalid_period`, `missing_media`, `generation_error`, `context_persistence_failed`. |
| `persisted` | `true`/`false`, если операция пыталась сохранить сгенерированный контекст; иначе `null`. |
| `cache_hit` | Признак использования video cache, если применимо. |
| `response_message_id` | Реальный Telegram id основного status/result сообщения, если оно создано. |

Терминальные значения означают:

- `succeeded`: основное действие завершилось и обязательные для него записи успешно сохранены;
- `rejected`: действие не начиналось из-за access check, отсутствующего аргумента/media, выключенной фичи, неверного периода или неоднозначного участника;
- `partial`: полезный результат отправлен, но необязательная запись контекста или video cache не сохранилась;
- `failed`: провайдер, download/recognition/generation или необработанный внутренний шаг завершился ошибкой.

Slash- и routed-вызовы проходят через общие wrappers и пишут один terminal `operation_outcome` event. Event содержит chat/message ids, способ вызова, action/reason роутера, elapsed time, provider/model и поля outcome. Пользовательские query, transcript и другой сырой контент в этот event не включаются. При включённом Opik те же безопасные metadata добавляются в текущий span/trace.

Необработанное исключение сначала логируется как `failed/unhandled_exception`, затем пробрасывается в aiogram; оно не маскируется ложным успехом.

## Принятые исключения

- `run_meme` и `run_transcribe` пока сохраняют legacy-сигнатуру без типизированного `OperationOutcome`. Wrapper нормализует их обычный возврат в `succeeded/completed`. Полная детализация их ранних отказов отложена; это не блокирует Feature 03, потому что эти операции не начисляют очки.
- `/stats` намеренно не проверяет `ALLOWED_CHAT_IDS`. Это discovery endpoint: он показывает `chat_id` и поле `access_allowed`, чтобы оператор мог настроить allowlist. Остальные команды, passive persistence и routed actions продолжают проверять доступ.
- Любой участник разрешённого чата может выполнять `/alias add`, `/alias remove` и `/alias list`. Admin-only политика из ранней спецификации отклонена. В будущем можно добавить отдельный необязательный admin-only toggle, но сейчас настройки и реализации такого toggle нет.
- Профили являются chat-scoped общим ресурсом: любой участник разрешённого чата может показать профиль другого участника по reply/имени, а также исправить или забыть его факты существующими `/profile correct` и `/profile forget`. Это принятое поведение совместного чата, а не приватное персональное хранилище.
- Feature 02.5 не меняет `handle_as_tasks=False` и не перестраивает общую модель GPU-очереди.

## Политика сохранения результатов

Исходная адресованная пользовательская реплика сохраняется до роутинга и не заменяется результатом операции.

- Успешные wiki/image/video/YouTube результаты пытаются сохраниться как отдельный контекст с реальным Telegram `message_id` status/result сообщения для routed-вызова. Slash-путь сохраняет существующую привязку, пока Feature 03 не введёт явное происхождение строк.
- Сообщение `Saved for summaries.` показывается только после успешного SQLite write.
- Если генерация или распознавание уже завершились, но SQLite write контекста не удался, результат всё равно отправляется пользователю. Интерфейс показывает безопасное предупреждение `Результат получен, но сохранить его для саммари не удалось.`, а outcome становится `partial/context_persistence_failed`.
- Текст исключения SQLite не показывается пользователю. Полная ошибка остаётся в server log.
- Для нового video recognition отдельно учитываются cache persistence и context persistence. Сбой одной или обеих записей не уничтожает уже полученный результат; outcome содержит `partial` и точную агрегированную причину.
- Cache hit также повторно пытается сохранить контекст выбранного результата и честно сообщает исход этой записи.
- Wiki без результатов завершается `succeeded/no_results`, `persisted=null`: пустой результат не объявляется сохранённым.
- Summary, question, profile и meme в Stage 02.5 не добавляются как новые строки контекста. Voice transcription сохраняет существующую политику замены/заполнения строки исходного voice/audio.

Эта политика не определяет eligibility для Joke Points. Feature 03 добавит явные provenance-поля и deny-by-default фильтр; успешное сохранение для саммари само по себе не делает строку кандидатом на награду.

## Surprise Meme Policy

Неожиданный мем является узким продуктовым исключением, а не fallback для ошибки роутера.

Мем создаётся с вероятностью ровно `2%` (`random_value < 0.02`) только если одновременно выполнены все условия:

- роутер вернул валидный `action=question` с `reason=ok`;
- очищенный адресованный запрос явно просит пошутить/рассмешить;
- в текущем сообщении или replied-сообщении есть изображение;
- выпала 2% вероятность.

Latest image из истории не удовлетворяет условию surprise meme. Невалидный JSON, timeout, `none`, `meme_not_explicit`, явный `meme` и любой другой action не запускают surprise meme. В этих случаях применяется обычный контракт route/fallback. Явная просьба `сделай мем` остаётся обычным intent `meme` без вероятности.

## Защита intent-ов

- `meme` допускается только при явном слове `мем`/`meme`; просьба пошутить классифицируется как question.
- `profile_show` допускается только при явном слове `профиль`/`паспорт`. Вопросы о имени, модели и возможностях бота остаются question.
- Если модель выбрала `wiki`, но не вернула непустой query, бот спрашивает `Что именно найти в Википедии?`. Он не запускает поиск и не превращает запрос в contextual question.
- `bot_command` проверяется и в `entities`, и в `caption_entities`; slash-команды в media caption не сохраняются как обычный текст и не попадают в роутер.
- Router unload завершается под GPU lock; выбранная операция запускается только после освобождения router lock.

## Алиасы и опечатки

- Алиасы нормализуются через Unicode NFKC, lower-case, `ё -> е` и токены букв/цифр.
- Совпадение идёт по целым токенам, а не по подстроке.
- Если суммарная длина нормализованного алиаса меньше 5 символов, допускается только точное совпадение.
- Для алиаса длиной от 5 символов допускается не более одной вставки, удаления или замены на весь алиас.
- Для многословного алиаса одна опечатка разрешена только в одном несовпадающем токене. Одна ошибка в каждом из двух токенов уже отклоняется. Это политика «одна опечатка всего», а не «по одной на слово».
- Несколько найденных алиасов удаляются, но update обрабатывается один раз.

## Profile Sharing

- `/profile` без reply и имени показывает профиль автора команды.
- Reply имеет приоритет и позволяет показать профиль автора replied-сообщения.
- `/profile <name>` ищет участника только в текущем чате. Неоднозначность и отсутствие совпадения требуют уточнения; fallback на профиль отправителя запрещён.
- Routed `profile_show` отвечает reply на адресованное сообщение; slash-вызов использует обычный answer.
- Пустой собственный профиль дополняется подсказкой, как выбрать другого участника.
- Вопрос использует релевантные profile facts автора и автора replied-сообщения, если они доступны.
- Alias-ы текущего чата передаются assistant-у как identity context, чтобы ответ на вопрос об имени учитывал настроенные имена бота.

## Тесты

Текущая regression-сетка:

- `tests/test_operation_stabilization.py`: подтверждение persistence только после write, безопасное предупреждение при SQLite failure, content-free structured outcome event;
- `tests/test_intent_router.py`: строгий JSON, стабильный `missing_wiki_query`, meme/profile explicit guards, timeout/model fallback, unload-before-unlock, surprise meme policy, `bot_command` в text/caption;
- `tests/test_addressing.py`: нормализация, token boundaries, короткие/длинные алиасы, одна общая опечатка в многословном алиасе, две опечатки отклоняются, mention/text_mention;
- `tests/test_storage_aliases.py`: uniqueness и chat scope aliases;
- `tests/test_assistant_identity.py`: chat aliases в identity context;
- `tests/test_youtube.py`: URL validation, reply priority, limits, cleanup и timeout cancellation;
- `tests/test_video_audio_chunks.py`: bounded audio chunks.

Проверки:

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m compileall src
```

Тесты используют fakes и временные SQLite базы; `.env` и `data/` не нужны.

## Критерии приёмки

- Каждая переведённая на outcome операция заканчивается одним структурированным terminal event для slash или routed invocation.
- Event не содержит query/transcript/user content.
- Ошибка сохранения wiki/image/video/YouTube не скрывает полученный результат и не показывает секретные детали БД.
- `Saved for summaries.` невозможно показать до успешного write.
- Missing wiki query всегда просит уточнение и не запускает другое действие.
- Surprise meme возможен только по формуле valid question + explicit joke request + current/replied image + 2%.
- Невалидный route никогда не вызывает surprise meme.
- Многословный алиас допускает одну опечатку суммарно и отклоняет две.
- Любой участник разрешённого чата может управлять aliases; код не делает admin lookup.
- `/stats` отвечает даже чату вне allowlist и явно показывает `access_allowed: false`.
- Показ/исправление/удаление profile facts другого участника остаётся chat-scoped совместным поведением.
- Полный unittest suite и compileall проходят без доступа к реальным данным.

## Явные исключения из объёма

В Stage 02.5 не входят и не считаются реализованными:

- Feature 03 `Joke Points and Leaderboard`;
- provenance migration для `messages`;
- `JokeSelector`, выбор winner и секция validated best joke;
- `chat_point_ledger`, `chat_point_balances`, `/balance`, `/top` и лидер в `/stats`;
- начисление `+10`, защита от повторной награды и любые balance transactions;
- разделение GPU lock для summary и будущего selector;
- Feature 04 casino, ставки, выплаты и переводы очков;
- admin-only alias toggle;
- изменение privacy-модели общих profile facts.

Feature 03 должна начинаться только после принятия этого контракта и следовать отдельному плану [[03 Joke Points and Leaderboard]].
